Contexte

De nombreux produits de l'enseigne « Les Halles by Chazal » n'avaient pas encore de photo sur le site. Ajouter une image demandait plusieurs manipulations manuelles, réparties entre différents emplacements de fichiers, sans moyen simple de savoir quels produits en manquaient.

L'objectif : un seul outil, branché sur l'API d'administration du site e-commerce, pour contrôler et compléter les photos sans passer par le back-office.

Fonctionnalités

  • Recherche par code, libellé ou fournisseur, recherche de plusieurs codes à la fois, filtres catégorie et sous-catégorie, pagination.
  • Articles récents : les produits créés sur les 7, 30 ou 90 derniers jours, pour traiter les nouveautés en priorité.
  • Import en masse : on glisse des dizaines de fichiers, le code produit est lu dans le nom de chaque fichier, puis l'utilisateur valide avant l'envoi.
  • Photos web et HD : la version web est mise au format du site, l'original HD est conservé sur Amazon S3.
  • IA générative : génération d'un visuel à partir du libellé, détourage sur fond blanc, changement de fond (10 fonds prêts ou un fond personnalisé), retouche libre par prompt, amélioration de la netteté.
  • Images d'ambiance : une même mise en scène rattachée à plusieurs produits.
  • Ma liste et historique : une liste de travail exportable dans Excel, et l'historique des dernières actions sur les images.

Comment une photo est traitée

  1. Dépôt

    L'utilisateur dépose une ou plusieurs images ; le code produit est détecté dans le nom du fichier.

  2. Original HD vers S3

    Le fichier original part tel quel sur Amazon S3 via un micro-service Node.js — ce qui contourne la limite de taille de l'API d'administration.

  3. Mise au format web

    L'image est centrée sur un fond blanc de taille fixe (1024×768, 1280×1024 ou 1600×1200 selon la source), avec une marge, puis compressée en JPEG.

  4. Envoi au site

    La version web est envoyée à l'API du site, et une copie est gardée sur S3.

  5. Vérification

    L'outil vérifie que l'URL renvoyée est réellement accessible avant d'annoncer la réussite.

  6. Vers l'ERP

    Chaque jour, un script Python copie les nouvelles photos web vers la GED de l'ERP (voir le projet dédié).

Architecture & déploiement

L'interface est en Vue 3 (Vite). Un micro-service Node.js (Express, Multer, sharp, AWS SDK) gère tout ce qui touche à S3 et aux fichiers lourds. L'ensemble tient dans une seule image Docker multi-étapes : Nginx sert l'interface et fait office de proxy vers l'API et le micro-service, ce qui règle aussi les problèmes de CORS. Le tout est déployé sur l'intranet avec Coolify.

Côté sécurité, les appels sensibles passent par le serveur : le navigateur ne reçoit qu'un jeton de session temporaire, et les clés d'API (IA, compte technique) restent côté serveur, dans des variables d'environnement. Le micro-service n'accepte que les dossiers et les hôtes prévus.

Difficultés rencontrées

Limite de requêtes de l'API

Problème Les recherches de nombreux codes ou sous-catégories déclenchaient des erreurs 429 (trop de requêtes).

Solution Appels espacés et séquentiels, nouvelles tentatives avec une attente qui double, verrou pour éviter deux connexions simultanées.

Fichiers trop lourds

Problème L'API d'administration refusait les photos HD (erreur 413).

Solution Ajout d'un micro-service Node.js qui envoie les originaux directement sur Amazon S3.

Images envoyées mais introuvables

Problème Environ 270 images avaient été envoyées avec des URL cassées, sans aucune erreur visible.

Solution Journalisation des échecs et vérification systématique de chaque URL après l'envoi.

Accents mal encodés

Problème Certains libellés arrivaient avec des caractères doublement mal encodés.

Solution Correction automatique de l'encodage à l'affichage.
